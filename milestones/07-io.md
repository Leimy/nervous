## Goal

Let a running process produce host-visible output through the same reserved-intrinsic/bytecode/host-callback pattern already used for `self`, `send`, `spawn`, and `receive`, without reopening the portable machine boundary (D010) or introducing anything resembling a general FFI (D053).

## Scope

- Two reserved intrinsics, `print(value)` and `eprint(value)`, writing a term to host stdout and stderr respectively (D054).
- Two new bytecode instructions, `print dst value` and `eprint dst value`, each dispatched through its own new `NvExecHost` callback slot, following the `Oself`/`Osend` two-register shape: one source register, one destination register, faulting `bad_process_context` when no host (or no callback for that operation) is installed. An earlier draft of this section said "one new bytecode instruction ... no destination register"; both parts were wrong (D054 explains why) and are superseded by this bullet and by "Settled interfaces" below.
- Rendering reuses the existing `nvvalueprint` term formatting (integers, atoms, tuples, PIDs, Refs) rather than inventing a second textual representation.
- The scheduler/CLI installs the callbacks against the real stdout/stderr `Biobuf` `cmd/nervous/main.c` already opens; `nvexecute`'s standalone (hostless) path continues to fault `bad_process_context` exactly like the other process intrinsics, consistent with D043.

## Explicitly not in this milestone

- Reading any input (stdin, files, network). That needs an opaque handle term (D053) and is deferred to a later milestone, likely after milestone 09 (Binaries) so reads can produce real binaries instead of ad hoc integer/tuple encodings.
- Any general FFI, arbitrary C call, or raw file descriptor exposed to bytecode (D053, permanently, not just for this milestone).
- Buffering/flushing policy beyond "correct and simple"; performance tuning is out of scope.
- Any change to process ownership, GC, or heap representation; this milestone touches none of it.

## Settled interfaces

Normative text is D054 through D057. This section names the concrete shapes implementers must build to.

Source and AST. `print(value)` and `eprint(value)` are reserved intrinsic call expressions, exactly like `self()`/`make_ref()`/`send(...)`/`spawn(...)`/`exit(...)`: no new `Expr` kind, just two more names recognized by the compiler's intrinsic dispatch and added to `reserved()` so they can no longer be used as ordinary function names.

Bytecode. Two new opcodes, `Oprint` and `Oeprint`, each with the operand shape `dst value` (two registers, matching `Otailcall`/`Orecvbegin`/`Orecvnext`'s operand count, not `Osend`'s three). The symbolic text form is `print dst value` / `eprint dst value` (see `../docs/bytecode.md`).

Host boundary. `NvExecHost` gains two callback slots:

```text
int (*print)(void *aux, NvValue *value, char *err, int nerr);
int (*eprint)(void *aux, NvValue *value, char *err, int nerr);
```

Each reads one value and reports 0 on success or -1 with a reason (`io_error` on a host write failure). Unlike `self`/`send`, the callback does not produce the destination value: `nvexecrun` itself writes the fixed atom `'ok` into `dst` on success (D055), the same way arithmetic instructions construct their own result rather than asking a callback to. A `nil` callback pointer (no host, or a host that chose not to wire this operation) faults `bad_process_context`, exactly like every other process instruction.

Scheduler wiring. `NvScheduler` gains an `NvIO` pair of optional output `Biobuf *` pointers (`out`, `err`) and `nvschedsetio(NvScheduler *, NvIO *)` to install or clear them, mirroring `nvschedsetclock`. Unlike the clock, there is no default: passing `nil` (or never calling it) leaves both unset, so `print`/`eprint` fault `bad_process_context` under a scheduler that never opted in, matching every process test and fixture that does not need output. `nvschedspawn` snapshots the currently installed `NvIO` into each newly spawned process's host struct, wiring `host.print`/`host.eprint` only when the corresponding `Biobuf *` is non-nil; callers must call `nvschedsetio` before spawning any process that needs it, since spawning after the fact does not retroactively rewire already-spawned processes. `cmd/nervous/main.c`'s `-r` path installs the same `Biobuf` already used for the final root-value report as `out`, and a second `Biobuf` on fd 2 as `err`, before spawning the root process.

Rendering and return value. Both instructions call `nvvalueprint` on the value (unchanged rendering: an atom keeps its leading quote, e.g. `'hello_world`) followed by a newline, then flush; on success `dst` becomes `'ok`. A flush failure faults `io_error`.

Reduction and lifecycle accounting. Each dispatch is one reduction (D030); neither instruction yields or changes process state (D041). A process that calls `print`/`eprint` and continues is scheduled identically, quantum-for-quantum, to one that instead executed any other single non-blocking instruction.

Ordering. D057's guarantee: with one scheduler dispatching one process per quantum, output from different processes is already totally ordered by dispatch order, and a single call's write is never interleaved mid-value with another process's. This is a property of the current implementation, explicitly not yet a promise past milestone 10 (multicore), which must revisit it if more than one scheduler can call host I/O concurrently.

Only now should the coordinator create disjoint parser/compiler, runtime/host, and test tasks if this were split further; in practice M07-T02 does all of it in one self-executed pass (see `STATUS.md`), matching the M06-T02/T03 precedent.

## Required tests

Each item below names the fixture(s) that implement it, so this list cannot silently drift from the tree the way an earlier draft's test list once did.

- A process that prints, then continues, is byte-identical in scheduling behavior to one that does not print: pinned as "one ordinary reduction, never yields, never changes process state" and checked by comparing dispatch/completion/step counts against a variant with the print instruction replaced by `nop`, under a one-reduction quantum so the comparison needs no freed-memory access. `tests/process/iotest.c`, using a `/dev/null` `NvIO` sink (no pipe involved, so 9front's closed-pipe write note never applies).
- Printed output for every existing term kind (integer, atom, tuple, PID, Ref) matches `nvvalueprint`'s existing rendering exactly, including the leading quote on atoms. `tests/process/cli/print-kinds.nv` + `.out`.
- `print` and `eprint` fault `bad_process_context` under `nvexecute`'s standalone hostless path, exactly like `self`/`send`/`spawn`. `tests/vm/print-hostless.nvb`, `tests/vm/eprint-hostless.nvb` (via `nervous -x`).
- Two processes each printing several times produce output in dispatch order, not interleaved mid-value. `tests/process/cli/print-order.nv` + `.out`.
- `eprint`'s success path (not just its hostless fault) is exercised, writing to stderr while stdout carries only the root report. `tests/process/cli/eprint-ok.nv` + `.out` + `.err`.
- A verifier-negative fixture (bad operand register) is rejected before execution, matching every other instruction's verification discipline. `tests/bytecode/invalid/bad-print-dest.nvb` + `.err`; `tests/bytecode/valid/io.nvb` covers the corresponding round-trip.
- A host write failure (e.g. output redirected to a closed file descriptor) faults the writing process with `io_error` and leaves every other process unaffected. `tests/process/cli/io-error.nv` + `.err`, run with fd 1 closed rather than a pipe.
- The complete milestone 06 aggregate suite remains unchanged.
- The exit criterion itself: `examples/hello.nv` against `tests/process/cli/hello.out`.

## Exit criterion

`examples/hello.nv` (`fn main { print('hello_world) }`) runs via `nervous -r` and visibly prints `'hello_world` (with its leading quote, per `nvvalueprint`'s existing atom rendering) to stdout during execution, followed by the CLI's usual final root-value report (`'ok`, since that is what `print` returns) -- not only the final report by itself. All required tests above pass together with the complete existing aggregate suite. Per COORDINATION.md, a worker's (here, self-executed coordinator's) report is evidence, not acceptance: this milestone moves to `complete` in `STATUS.md` only after the user has actually run the tests and the example and confirmed the result, since the available tooling can compile but not execute programs.

## Not in scope

File, network, or any other host resource beyond stdout/stderr; general FFI; buffering/performance tuning; any opaque handle term kind (deferred to the later I/O-over-files milestone this one explicitly sets up for).
