# Adversarial Review Findings

This ledger persists review concerns across status rewrites. A finding is closed only by a fix with evidence or a written argument showing it is not a defect. Deferral requires a destination milestone and owner. Review gates apply the severity rules in `COORDINATION.md`.

Findings from a gate whose milestone state is permanently `complete` are relocated to `review-findings-archive.md` to keep this file short; a section left here as a short pointer means the gate is closed for good. Read the archive only when investigating a regression in already-closed work.

| R3-F02 | medium | closed | R3 coordinator (pre-gate, found by a Sonnet read-only audit of the M09 `bin*` opcodes, verified by the coordinator against `malloc(2)` and `include/nvvm.h`) | `nvfragcopy` (`lib/value.c`) computed the fragment size as a 64-bit `count*sizeof(NvTerm)` and passed it to Plan 9's `malloc(ulong)` unguarded, and stored `count` into `NvFrag.nword`, an `ulong`; both are 32 bits on this build. | R3-F04 | high | closed | R3 coordinator | Latency isolation (the third isolation leg, first measured by M09-T05): an instruction that traverses a term -- `testeq`, `print`/`eprint`, the root `return`/`exit` copy, `spawn`'s argument copy -- cost one reduction however many nodes it visited, and visits are exponential in depth on an independently built shared graph. | R3-F05 | high | closed | R3 coordinator (found by the user's `nervous_gcstress=1 nervous_gcoffload=1 rc tests/run.rc` run failing intermittently in `offloadtest.c:holddeadlock`; diagnosed from `sched.c`/`exec.c` source) | Off-process collections launched by the idle sweep collected nothing. `collectorchild` called `nvexecgc(e)` unconditionally, but `nvexecgc` begins `if(!e->gcpending) return;` -- it services a pending *demand* reservation, and an idle-sweep launch has none (the inline idle path, `doinline`, correctly calls `nvexeccollect(e, 0)` instead). So under any nonzero `gcoffload`, every idle-sweep launch was a fork that did no work, published idle, folded as a failure (`gcretry == 0`), left `livewords` stale, and left the waiting process eligible for another no-op launch on the next idle pass -- forever: waiting processes' garbage was never reclaimed off-process, one fork per idle pass. `holddeadlock`'s final `NvSchedIdle` check was therefore a race between the second no-op child's publish and the same step's `gcfoldall`: it passed when the child was fast, and failed under the loaded suite run. Unreachable at the default `gcoffload = 0` (D075), hence never seen by the CLI runs; high because it silently defeats the memory milestone's core guarantee for anyone who opts in, and turns the "never spin" idle wait into fork-per-pass. | `collectorchild(e, demand, ...)` now mirrors `doinline`: demand -> `nvexecgc`, idle -> `nvexeccollect(e, 0)`. The outcome is reported through a new `NvExec.gcresult` (1/2/3) rather than `gcretry`, because `gcretry` is the interpreter's retry state for a pending reservation and an idle collection must not touch it; `gcfold` reads `gcresult` under the lock. `holddeadlock` now asserts `collections == 1 && gcfailed == 0` and `livewords == heap.words` after the fold (fails deterministically on the old code); `holdsweepcap` asserts `gcfailed == 0 && collections >= N`; `holdfalseidle`'s hook sets `gcresult`. `mk tests benchmarks` clean. User reports all three suite invocations passing on the fix, including the gcstress+gcoffload run that exposed it. Closed. |
| R3-F06 | medium | closed | R3 coordinator (found while diagnosing R3-F05) | `nvschedfree` could free `gcsem` while a collector child still had to touch it. The child publishes idle (under the heap lock) and *then* `semrelease`s; the scheduler folds as soon as it observes idle, so `gcdrain`'s `gcoutstanding == 0` is true before the child's last shared-memory write. A child descheduled between `unlock` and `semrelease` then increments a freed 8-byte block -- in the test binaries, plausibly the next scheduler's freshly `mallocz`'d `gcsem` or `gchold` (a stray increment of `gchold` would park that scheduler's collectors indefinitely). Not the cause of the observed failure, but a real use-after-free at teardown that D074's "drain before freeing anything a collector might still hold a pointer into" was meant to exclude. | Every successful fork counts in `NvScheduler.gclaunched`; every consumed semaphore credit (all four `tsemacquire` sites now go through `gcwait`) counts in `gccredits`; `gcdrain` waits, bounded and failing loudly like its existing drain, until `gccredits == gclaunched` before returning, so the last `semrelease` of every child has executed before `gcsem` is freed. No deterministic regression is practical (the window is between two adjacent instructions in the child); closure rests on inspection plus the suite; user reports all three invocations passing. Closed. |
